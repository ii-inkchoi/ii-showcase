Goal

Move the Active Position list from a broker view (balance + recent change) to a decision-system view (commitment context). The list is an orientation surface; calibration depth lives on Stock Detail.

“We're not building an investing app. We're building better investors.” — Mogo Design Philosophy

Changes from Chairman v2 — Rationale

# Change Rationale
1 Add account scope label above page title (e.g., “RRSP”, “All accounts”) A bare percentage like “74%” is not a self-describing statement. Its meaning depends on the scope (RRSP weight vs. all-accounts weight differ for the same stock). Without an explicit scope label, the user must infer or guess what the percentage refers to. Surfacing the scope as a small persistent label removes that ambiguity. This is required by Doctrine §10 (statements over explanations) — “5%” alone is not a statement; “5% of RRSP” is.
2 Held column → Held / Horizon (e.g., 1.5y / 3y) A raw “time held” number is automatic data — it tells the user what the system already knows. What matters in II is whether the user is honoring the commitment they made at entry. Showing held / horizon reframes the column from elapsed time to progress against the user's own commitment, making Doctrine §11 (friction at decision moments) and §13 (memos as living documents) visible at the list level. When held equals horizon, that itself is a signal for re-calibration.
3 Remove daily price and daily ±% from the row Doctrine §15 is explicit: minimize intraday noise; activity correlates negatively with returns. Daily ± in the primary list trains the user to glance daily and react. The Value column already reflects today's price (market value = shares × current price), so today's impact is implicit; an explicit % invites yesterday-vs-today comparison, which activates Doctrine §3 Enemy (Noise + Short-termism + Impulse). Daily price inspection has a deliberate place — the Stock Detail / Market tab — which the user reaches by intent.
4 Move CAD currency notation from per-row to column header (“Value CAD”) All values in the list are auto-converted to CAD (USD positions included). Repeating “CAD” on every row adds visual weight without adding information once the user understands the column. Single notation in the column header is sufficient. Doctrine §1: do not explain more than is necessary.
5 Calibration data deliberately NOT in list — confidence and calibration plot live on Stock Detail only Calibration is the heart of the system, but the Active Position list is an orientation surface (Doctrine §14 logic, applied here to the list). A paired numeric like 80%·76% requires header-level explanation to be parsable, and that explanation itself adds visual weight that contradicts Doctrine §1. The Stock Detail calibration plot — a line with a dot above or below — is visually self-explanatory and is the right home for the challenge. Concentrating calibration analysis on the surface deliberately built for it also avoids retraining the user to glance daily at a self-evaluation metric (Doctrine §15).
6 Alignment per Mogo Design Philosophy §8 Alignment Rules Doctrine §8 says “no centering, ever.” It does not say everything must be left. The MVP system has already converged on a coherent convention: page titles right-aligned (anchor of identification), numeric columns right-aligned (functional magnitude scanning), prose and text labels left-aligned. v3 follows that system convention rather than introducing a one-screen exception. The doctrine file §8 has been updated with an Alignment Rules subsection.

What v3 deliberately keeps from v2

The right-aligned page title, the dense tabular layout, the absence of brand color, sans-serif typography, and asymmetric composition all carry forward unchanged. v3 is not a stylistic departure from Chairman v2 — it is a tightening of intent.

Doctrine references

  • §1 — Do not explain more than is necessary. Mystery is preserved by withholding.
  • §6 — ICP: willing to be measured, challenged, and proven wrong in order to improve.
  • §8 — Visual Design (Severe Mode). Alignment rules.
  • §10 — Tone of voice. Statements over explanations.
  • §11 — Friction Doctrine. Friction belongs at capital allocation, not at reading flows.
  • §13 — Memos as Living Documents. Records of thought over time.
  • §14 — Dashboard restraint. Orientation surface, not decision surface.
  • §15 — Behavioral Constraints. Silence is a feature.

Dependencies

Calibration page (currently WIP) must capture probability and horizon at buy time for Held / Horizon to function on this list. An account scope model coherent across Dashboard, Active Position list, Stock Detail, and Holdings is required. USD-to-CAD conversion logic in the data layer must support consistent per-stock CAD values.

What this list is not

It is not a place to track daily price movement. It is not a calibration analysis tool. It is not a navigation hub for switching accounts. It is the orientation surface that answers a single question: what do I own, and how meaningful are those decisions?
