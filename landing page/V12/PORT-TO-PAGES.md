그대로 붙여넣으면 된다:

읽는 쪽이 알아야 할 전제:

## 2. V11 index.html 의 구조 — 어디를 고쳐야 하나

블록 4 개가 파일 끝에 붙어 있다. **어느 블록에 넣느냐로 적용 폭이 결정된다.**

| 블록 | 적용 범위 |
|---|---|
| `<style id="v11-mobile">` | `@media (max-width:900px)` 안. **모바일 전용** |
| `<style id="v11-global">` | 미디어쿼리 **밖** = 양쪽. 안쪽에 `@media (min-width:901px)` 블록이 따로 있음 = 데스크탑 전용 |
| `<script id="v11-newsroom">` | 뉴스룸 DOM. **전 폭** |
| `<script id="v11-price">` | `$20` 피겨 분리. **전 폭** |
| `<script id="v11-footer">` | 푸터 법무 문단 래퍼. **전 폭** |

**한 벌의 DOM 을 두 폭의 CSS 가 각각 입힌다.** 데스크탑용 사본을 따로 만들지 말 것 — 다음에 한쪽만 고치게 된다.

## 3. 오늘 확정한 규칙 — 이식할 때 이게 기준이다

### 3-1. 타입 사다리 (두 폭 모두 실측 확인, 사다리 밖 0 개)

> **★ 2026-08-18 갱신 — 이 표의 데스크탑 열은 "노트북에서 플로어에 바닥 찍은 상태" 였다.**
> 플로어를 한 칸씩 올렸으므로 (§4-1 #22) 1512 의 데스크탑 사다리는 이제
> **48 · 28 · 22 · 17 · 15 · 13 · 11** 이다. 아래 표는 갱신 전 값이니 그대로 믿지 말고
> `HANDOFF-V11.md` §2-3b 를 함께 볼 것. 2545 마스터에서는 아래 표가 아니라 마스터 값
> (64 / 34 / 27 / 24 / 22 / 17 / 15 / 13 / 11) 이 렌더된다.

**크기**

| | 모바일 (375) | 데스크탑 (1440) |
|---|---|---|
| sans | 11 / 13 / 15 / 17 / 22 / 28 / 34 | **11 / 13 / 15 / 17 / 22 / 28 / 34 / 48** |
| mono | 9 / 11 / 13 (+15 는 `+` 기호 전용) | **11 / 13 / 15** |

> **★ 폭을 반드시 적을 것.** 데스크탑 값은 2026-08-18 의 플로어 수정 이후다. 그 전에는 노트북이 모바일 사다리(38·22·17·15·13·11)로 렌더되고 있었다 — 표에 폭이 없으면 다음 감사자가 이 수정을 위반으로 잡는다. 근거는 `HANDOFF-V11.md` §2-3b, DS 의 `Desktop ladder (≥901px)`.
> **데스크탑 블록에 px 을 박지 말 것** — 플로어가 바뀌면 혼자 남는다. `var(--t-*)` 를 쓸 것.

**행간**

| 모바일 (5 값) | 데스크탑 (7 값) |
|---|---|
| 1.10 디스플레이 | **0.90 밴드 마스트헤드** (`.hbar`) |
| 1.15 스탯 피겨 | 1.05 섹션 타이틀 |
| **1.25 22 티어** | 1.15 항목 제목 (17) |
| 1.40 산문 + 모노 메타 | **1.25 22 티어** |
| 1.50 모노 라벨 | 1.30 산문 (15/17) |
| | 1.40 모노 메타 · 1.50 모노 라벨 |

- **`1.3` 은 모바일에서 금지** (데스크탑 산문 값이 새어내려온 것으로 읽힌다). 현재 실측 0 개
- **0.90 은 원래 캐논이다.** DS 랜딩 섹션과 `Doctrine/Typography.md` §5 에 처음부터 있었다 (`.hbar` = 0.9). V11 인수 문서에만 없었을 뿐이라 내가 한때 "미기록 티어" 로 잘못 적었다. 섹션 타이틀(1.05)과 역할이 다르다 — 사진 위 마스트헤드. **1.05 로 흡수하지 말 것**

**자간:** −0.069em (스탯 피겨) · −0.02em (디스플레이) · 0 (산문·22 티어) · +0.04em (모노)

**22 티어 = 400 / 1.25 / 자간 0**, 두 폭 공통. 22 로 렌더되더라도 **스탯 피겨(`.g2stat .v` 등)는 제외** — 400 으로 내리면 숫자가 산문으로 납작해진다.

### 3-2. ★ 모노 행간은 크기가 아니라 역할

규칙이 두 곳에 있고 **뒤엣것이 이긴다**:

| 어디 | 내용 |
|---|---|
| 베이스 시트 (`.eyeb,…{1.5}` / `.figcap,…{1.4}`) | 역할별: 1.5 라벨·CTA / 1.4 메타 |
| 모바일 블록 (2026-08-01, 인경, "all pages") | 더 구체적: **행간은 줄바꿈되는 텍스트에만 일한다.** 한 줄짜리 라벨 박스는 높이만 정하므로 1.5 유지 |

그래서 `01`–`04`(한 글자) = 1.5, `.fee`·`.figcap`(문장) = 1.4.

> **주의.** 나는 여기 없는 세 번째 규칙 **"11px 티어 = 1.4"** 를 상상해서, 맞는 값을 틀린 근거로 바꾸고 → 베이스 시트를 발견하곤 **맞는 값까지 되돌렸다.** 세 라운드를 썼는데 실제 차이는 **1.1px, 줄바꿈도 없는 한 줄**이었다.
> **모노 행간 0.1 차이는 보고 대상이 아니다.** 눈에 보이는 크기 차이만 올릴 것.

### 3-3. 표식이 곧 동작

| 표식 | 뜻 |
|---|---|
| **↗ 화살표** | 이 화면을 **떠난다** (다른 페이지 · 앵커) |
| **+ 부호** | **제자리**에서 펼친다 |
| **박스** (무표식) | 박스 형태가 표식 |
| **밑줄만** | 본문 문장 안의 인라인 링크 |

양방향으로 성립해야 한다 — **표식 없이 누를 수 있는 것도, 누를 수 없는데 `role="button"` 인 것도 없어야 한다.**

**검사 함정:** `+` 는 세 방식으로 들어간다 — `.suit5` 는 **`::after` 의사요소**, `.tmore` 는 `<span class="sign">`, `.vmemo` 는 `<i>`. `textContent` 만 보면 `.suit5` 를 "표식 없음" 으로 오판한다 (실제로 오판했다). `getComputedStyle(el,'::after').content` 까지 볼 것.

### 3-4. 간격 사다리 (모바일)

**24 / 48 / 104** 세 값. 24 = 비트 안의 스텝, 48 = 비트 안의 그룹 경계, 104 = 비트 사이.
판정 질문: **"이 둘은 다른 아이디어인가, 한 아이디어의 다음 걸음인가?"**

**8 / 16 은 요소 *안*의 값** (라벨→값, 제목→요약). 사다리는 요소 *사이*를 규율한다.

## 5. 이식 순서 — 2026-08-19 부터 완전히 달라졌다

> **이 절의 옛 내용(항목별로 페이지마다 복사)은 폐기됐다.** 그 방식이 만든 결과가 Managed 의 갈림이다. 지금은 공유 레이어가 있다 — `shared/v11.css` + `shared/v11-sub.js`. 절차 전문은 **`shared/README.md`**.

### 페이지 하나 붙이기

1. 페이지의 **마지막** `<style>` 블록 뒤에 `<link rel="stylesheet" href="shared/v11.css">`
2. 원래 인라인 스크립트들이 있던 자리에 `<script src="shared/v11-sub.js"></script>` (`defer` 금지)
3. `<body class="p-sub">` — 이게 서브페이지 히로를 켠다
4. 그 페이지 `v11-*` 블록에서 공유 파일이 이미 말하는 규칙을 삭제 (주석은 남긴다)
5. `python shared/check-v11.py`

### 페이지에 남는 것

`#섹션id` 리듬(비트 사이 여백)과, `#id` / `body.p-*` 로 키를 잡고 이유를 적은 페이지 예외. **그 외 크기·두께·행간·자간·선 처리는 공유 파일이 소유한다.**

### 페이지 고유로 남는 판단

1. `newsroom.html` — 홈의 뉴스룸 문법(#2)과 맞출지 결정 필요. 홈은 요약본, 뉴스룸은 인덱스라 **같아야 하는지가 먼저 정해질 사안** (§7-7)
2. `pricing.html` — `$20` 처리(#3)가 여기에도 있는지 확인
3. `press-release.html` / `changelog-entry.html` — `READ` 라벨 캐논(§3-5) 적용
4. **홈 스크립트 통합** — 홈은 자기 히로·푸터 빌더를 갖고 reveal 이 `script#v11-mobile-js` 안에 있어서 `v11-sub.js` 를 안 쓴다. 별도 작업 + 별도 검증

## 6. ★ 함정 — 오늘 실제로 밟은 것들

### 6-1. 특정성 — 하루에 세 번 밟았다

1. 22 티어 규칙을 블록 **중간**에 넣었더니 뒤쪽 동일 특정성 선언에 소스 순서로 밀려 **두께만 먹고 행간은 안 먹음** → 블록 맨 끝으로
2. 데스크탑 CSS 를 미디어쿼리 없이 넣었더니 **모바일이 깨짐** (`.clog .ci` grid→flex, 섬네일 88×56→335×56) → `@media (min-width:901px)` 로 가둠
3. 리빌 CSS 를 `min-width:901px` **안**에 심어 모바일에서 사라짐 → 밖으로

> **규칙:** 새 규칙을 넣을 때 ① **미디어쿼리 깊이(중괄호 균형)를 센다** ② 같은 선택자의 기존 선언이 뒤에 있는지 **grep 한다** ③ **양쪽 폭에서 실측한다.** 셋 중 하나만 빼도 위처럼 된다.

### 6-2. ★★ CSS 주석에 닫는 style 태그를 문자로 쓰지 말 것

주석 안이라도 **HTML 파서는 거기서 `<style>` 요소를 끝낸다.** 뒤쪽 CSS 가 통째로 죽는다. 태그 균형 검사(`<style` 4 / `</style>` 5)로 잡았다.

### 6-3. 효과가 자기 트리거를 막는다

`clip-path:inset(0 100% 0 0)` 로 폭을 0 으로 자르면 IntersectionObserver 가 그 요소를 **면적 0 (ratio 0.00)** 으로 본다. 화면 정중앙에 있어도 발화하지 않는 교착. → **래퍼를 관찰**하고 rootMargin 을 당길 것.

### 6-4. 그리드 자동배치는 sparse 다

`grid-column` 만 주고 `grid-row` 를 안 주면, 이미지가 1 행 2 열을 잡은 뒤 커서가 2 열을 지나가서 **DOM 상 뒤에 있는 텍스트가 1 행 1 열로 되돌아가지 못하고 2 행으로 떨어진다.** 나란히 서야 할 둘 사이에 화면 하나만큼 공백이 생긴다. **양쪽에 `grid-row:1` 명시.**

### 6-5. 기존 `grid-column:span N` 을 확인하고 열 수를 바꿀 것

`.ci` 는 `span 3` 을 갖고 있다. 스트립을 `repeat(3,1fr)` 로 바꾸면 카드 하나가 **스트립 전체**를 먹는다. 12 열 그리드를 두고 **카드의 span 을 조정**하는 게 맞다.

### 6-6. 브라우저 패널이 숨겨지면 페이지가 프레임을 안 그린다

`rAF` · IntersectionObserver · 스크린샷이 전부 멈춘다. **리빌이 "안 되는 것처럼" 보이는 원인의 대부분이 이것이었다.** 패널을 띄운 상태에서 잴 것.

### 6-7. "언제 실행됐나" 보다 "누가 했나" 를 먼저

비트 2 리빌이 스크롤 전에 다 소진되던 문제로 **타이밍 가설을 세 번**(rAF 1 회 → layout-ready 핸드셰이크 → load+120ms) 세웠는데 전부 헛다리였다. 실제 원인은 히로2 를 만들며 `classList.add('in')` 을 **강제로 붙이던 코드 한 줄**. 결정적 단서는 대상에 **인라인 `transition-delay` 가 없다**는 것 = `reveal()` 을 안 거쳤다 = 다른 경로가 있다.

### 6-8. 메모 목업은 랜딩 타이포가 아니다

`.dr-doc` / `dr3-*` 은 **프로덕트 UI 복제**라 자체 스케일을 갖는다. 랜딩 사다리로 재면 8 개가 위반으로 잡히는데 **전부 오탐**이다. audit 에서 제외할 것.

## 8. 검증 프로토콜 — 이대로 하지 않으면 숫자가 틀린다

1. **측정 전 트랜스폼을 강제로 끌 것**
   ```js
   var st=document.createElement('style');
   st.textContent='.rv,.ri{transform:none!important;opacity:1!important;clip-path:none!important}';
   document.head.appendChild(st);
   document.querySelectorAll('.rv,.ri').forEach(function(e){e.classList.add('in')});
   ```
2. **간격은 잉크 기준**으로 잴 것. 섹션 패딩만 재면 밴드 오버레이의 내부 여백을 놓친다
3. **DOM 순서가 아니라 시각 순서**로 정렬해서 잴 것 (`order` 가 걸린 요소가 있다)
4. **두 폭 다** — 375 와 1440. 폭을 바꾸면 반드시 리로드 (`resize_window` 는 `resize` 이벤트를 안 쏜다)
5. **파일 무결성** — 편집 후 매번:
   ```bash
   echo "NUL:$(tr -dc '\000' < index.html|wc -c) script:$(grep -o '<script' index.html|wc -l)/$(grep -o '</script>' index.html|wc -l) style:$(grep -o '<style' index.html|wc -l)/$(grep -o '</style>' index.html|wc -l) div:$(grep -o '<div' index.html|wc -l)/$(grep -o '</div>' index.html|wc -l)"
   ```
   OneDrive 동기화가 HTML 을 말없이 잘라먹은 전례가 있다. `</html>` 로 끝나는지도 확인
6. **큰 패치는 heredoc 말고 스크립트 파일로.** bash heredoc 이 따옴표에서 반복적으로 깨졌다. 스크래치패드에 `.py` 를 쓰고 실행하는 쪽이 안정적이다
