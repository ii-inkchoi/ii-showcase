### 3-1. ★ 데스크탑 타입 플로어 — 노트북이 모바일 사다리로 렌더되고 있었다

**발단**: 인경이 맥북으로 옮겨와 Anduril 과 대조하며 *"다 작아보여"*.

**원인**: `--u: calc(100vw / 2545)` — 데스크탑 타입은 2545px Figma 마스터에 비례한다.
각 토큰에 px 플로어가 있는데 **그 값이 모바일 값으로 설정돼 있었다.** 교차폭 아래에서는
플로어가 렌더된다:

| 토큰 | 마스터 | 옛 플로어 | 플로어 지배 폭 |
|---|---|---|---|
| `--t-body` | 22 | 15 | < 1735 |
| `--t-h34` | 34 | 22 | < 1647 |
| `--t-mono15` | 15 | 13 | **< 2206 (노트북 전 구간)** |
| `--t-mono13` | 13 | 11 | < 2153 |
| `--t-read27` | 27 | 17 | < 2544 |
| `--t-lead24` | 24 | 17 | < 1802 |
| `--t-small17` | 17 | 13 | < 1946 |
| 디스플레이 `64u` | 64 | **없음** | 계속 축소 |

**1512(맥북)에서 실제 렌더: 산문 15 · 라벨 13 · 메타 11 · 스탯 22 · 타이틀 38 = 모바일 사다리.**

**고친 것** — `style#v11-global` 안 `@media (min-width:901px)` 에서 `:root` 재정의:

```css
--t-body: max(17px,…)   --t-h34: max(28px,…)   --t-mono15: max(15px,…)
--t-mono13: max(13px,…) --t-read27: max(22px,…) --t-lead24: max(22px,…)
--t-small17: max(15px,…)
.hbar,.sys h2,.loop3 h2,.bigh2{font-size:max(48px, calc(64 * var(--u)))}
```

**1512 사다리: 48 · 28 · 22 · 17 · 15 · 13 · 11** (이전 38 · 22 · 17 · 15 · 13 · 11).

**왜 미디어쿼리 안이어야 하나**: 토큰은 `:root` 이고 **모바일에서도 16곳이 이 토큰으로 렌더**된다
(`--t-body` 8곳 = `.plead`·`.def4 .body`·뉴스룸 요약 등, `--t-h34` 2곳 = 뉴스룸 스트림 제목,
`--t-mono13` 2곳 = 히로 트러스트). 전역으로 올리면 다 같이 커진다.

**검증 방법 (그대로 재현할 것)**: 변경 전 파일을 `_before.html` 로 같이 서브하고, 각 폭에서
텍스트 노드를 가진 요소 전부의 `font-size` 를 순서대로 뽑아 1:1 대조.
**결과: 375 에서 149개 차이 0 · 2545 에서 202개 차이 0 · 1512 에서 135곳 상승.**

**48 플로어의 근거**: `.hbar` 는 `white-space:nowrap`. 1512 에서 가장 긴 줄
("The market remembers every decision.")이 48px 에서 869px, 레일 1497 안에 여유 382.
52·56 도 들어가지만 **48 이 1280 까지 안전** (1280 에서 밴드 6줄 최대 874, 넘침 0). 릴리즈 1909px.

폭이 60% 늘 때 타입은 27% 만 는다 — 완만히 스케일하고 무너지지 않는다.

## 6. SD — 목업 3개를 바텀시트로

**결정 과정 (내가 두 번 틀렸다)**:
1. 처음: *"시트 이득은 폭 40px 뿐"* → **폭만 재서 틀렸다.** 이득은 "화면"이 아니라
   **"인라인에서 빼는 것"** 이다
2. 다음: *"SD 는 프로덕트 페이지니 인라인 노출 유지"* → 인경 교정:
   **홈에 적용한 판단(공간 때문에 탭 뒤로)과 반대되는 말.** 같은 문제에 두 페이지가 다른 답을
   내면 사이트가 어긋난다. SD 는 목업이 **두 개(1,151px = 화면 1.4개)** 라 근거가 더 강했다
3. 홈 실측: 모바일에서 `.dr-doc{display:none}` · `.figcap{display:none}` — **티저도 크롭도 없고
   텍스트 링크 하나뿐.** 내가 본 `max-height:330px` 는 데스크탑 크롭이었다

**구현** (`script#v11-sheets`, 홈의 단일 메모 버전을 일반화):

| 시트 | 원본 | 방식 | 컨트롤 | 위치 |
|---|---|---|---|---|
| light | `#record .dr-doc` | 복제 | `VIEW THE FULL MEMO +` | 산문 뒤 |
| dark | `#calibration .cal-card` | 복제 | `VIEW THE FULL RECORD +` | 트리오 뒤 |
| light | `.close9 .constfig` | **이동** | `VIEW THE RECORD DIAGRAM +` | 오퍼 뒤 |

**★ 세 번째는 `<canvas>` 라 복제하면 빈 캔버스가 된다** (bitmap 은 clone 되지 않음).
실제 노드를 옮겨 스크립트의 참조를 살렸다. 그리기 루프가 rAF 연속이고 캔버스에
`ResizeObserver` 가 붙어 있다.

**★ 그래도 한 번 더 걸렸다**: RO 가 **숨겨진 동안 0 을 읽고 다시 발화하지 않는다**
(attr 0x0 with a 335×484 box). 시트 `open()` 에서 `resize` 이벤트를 **0 / 60 / 200ms 세 번**
쏜다. rAF 한 번으로는 부족했다 (실측). DOM/CSS 목업은 resize 를 무시하므로 무해하다.

**★ 스코프 함정**: 도해 레이아웃 규칙을 `.close9 .cols .constfig` 로 썼더니 노드가 시트로
이동한 순간 매치가 끊겨 데스크탑 기본값(78px)으로 돌아갔다. `.constfig` 로 다시 썼다.

**시트 CSS 요점**
- `.sheet{display:none}` 은 **미디어쿼리 밖** (`v11-global-sd`). 모바일 블록 안에 두면
  데스크탑에서 목업 복제본이 body 끝에 그대로 렌더된다 (실측함)
- `@media (min-width:901px){ .v11-sview{display:none} }` — 데스크탑은 목업이 인라인에 있으니
  링크가 불필요하고, 눌러도 `open()` 이 `matchMedia` 에서 막혀 **아무 일도 안 일어난다**
  (§2-6 위반: 표식이 있는데 동작 없음)
- `open()` 은 **클릭 시점에** `matchMedia` 재확인 (홈이 데스크탑 스크롤 잠김으로 배운 것)
- 복제 노드는 `.rv`/`.in` 을 벗긴다 (리빌 옵저버가 원본만 보므로 복제본은 opacity 0)
- `.v11-sview` 는 `align-self:flex-start` + `text-align:left` **둘 다** 필요.
  `<button>` 의 UA `text-align:center` 가 flex 자식으로 335px 까지 늘어나며 드러났고,
  `display:inline-block` 은 flex 자식에서 블록화되어 무력하다 (라벨이 x=96 에서 시작)

### 이번에 밟은 함정 4개

1. **주석 안의 중괄호** — CSS 를 규칙 단위로 파싱할 때 주석을 마스킹하지 않으면 주석 속 예시 코드를 규칙으로 읽는다. 그리고 `rfind` 로 찾은 주석 종료 위치는 별표의 인덱스라 `+1` 이 아니라 `+2` 여야 한다. 이거 하나로 셀렉터를 5 개밖에 못 찾았다.
2. **`link.disabled = true` 는 되돌아오지 않는다** — 크롬에서 한 번 끄면 다시 켜도 시트가 동기 복구되지 않는다. A/B 측정은 **켠 상태를 먼저** 재야 한다.
3. **셀렉터 목록에 접두사를 붙일 때 중복** — `.hero>video,.hero>img` 를 통째로 접두하고 다시 `.hero>video` 항목이 그 안에서 매치돼 `body.p-home body.p-home .hero>video` 가 됐다. body 안의 body 라 **아무것도 매치하지 않는다.** 히로 비디오가 조용히 1 뷰포트 높이를 잃었다.
4. **셀렉터 문자열 비교는 부족하다** — 같은 규칙이 페이지마다 목록 순서가 다르고, 선언이 두 규칙에 쪼개져 있기도 하다. 셀렉터 **집합** 포함 · 선언 **집합** 포함 (공유 쪽은 합집합) 으로 비교해야 한다. 그리고 **선언이 더 있는 규칙은 지우면 안 된다** — Managed 의 `min-height:167px` 가 그렇게 사라졌다.

### 클로즈 컨트롤 배치 (같은 날)

인경: "managed는 cta가 구분되어있고 sd에서는 같이 있어. 로직은?" — 로직은 절반만 있었다.

**있던 것:** 액션 그룹 = 박스 1 + ↗ 1 (세 페이지 동일). `+` 는 그룹 밖 (↗ 는 떠나고 `+` 는 제자리, 표식 체계 §2-6).
**갈린 것:** Managed `SELF-DIRECTED ↗` 만 ↗ 인데 프로즈 사이에.

내 첫 제안(앞 간격 24→16 으로 좁혀 소속을 보임)은 **틀렸다.** 인경: "다른 섹션에 문장과 cta 사이랑 맞춰야하지않나. 일단 그것부터 보고" → 실측하니 **문장→인라인 컨트롤은 전 페이지 24 캐논**이었다 (#development MANAGED, #research PRICING, VIEW THE FULL MEMO, REGULATORY STANDING 전부 24). 이어서 인경: "현재 공간이 다른 섹션과 같은 규칙이면 소속을 보이기 위해선 섹션안의 요소의 공간을 늘려야할듯" — **앞을 좁히는 게 아니라 뒤를 여는 것**이 맞다. 뒤에 48 을 넣었다.

### 이번에 밟은 함정 5 개 더

4. **주석 안에서 편집하면 `*/` 를 옮겨야 한다.** 주석 끝에 문단을 덧붙이면서 앞 `*/` 를 지우지 않아 뒤 산문이 CSS 로 파싱됐다. **세 번 반복했다.** 이후로는 v11.css 를 고칠 때마다 측정 전에 주석/괄호 균형부터 셌다.
5. **`.ri` 도 등장 애니메이션이다.** 콘텐츠 6 페이지는 `.rv` 가 아니라 `.ri` 를 쓴다. `.rv` 만 풀고 재서 pricing 항목 사이를 72 로 잘못 읽었다 (실제 48). 측정 전에 **두 클래스 다** 풀 것.
6. **HTML 엔티티가 대문자 검사를 통과시킨다.** `RESEARCH &amp; ANALYSIS` 는 글자만 남기면 `RESEARCHampANALYSIS` 가 되어 소문자 `amp` 때문에 "대문자 아님" 으로 새어나갔다. 검사기도 같은 구멍이었다. 엔티티를 먼저 풀고 판정한다.
7. **파일을 옮길 때 링크된 자산도 같이 옮긴다.** 6 페이지를 V11 로 복사하면서 그들이 링크하는 `mobile-canon.css` 를 빠뜨렸고, 그 상태로 한동안 측정했다.
8. **`html` 을 모듈 이름과 변수 이름으로 같이 쓰지 않는다.** `check-v11.py` 에서 페이지 소스 변수가 `html` 이라 `import html` 이 가려졌다. `from html import unescape` 로 함수만 가져온다.

### 이번에 밟은 함정 3개 더

1. **★ 리빌 트랜지션이 측정을 오염시킨다.** `.in` 만 붙이고 바로 재면 0.8s 트랜지션이 진행 중이라 요소가 아직 24px 내려가 있다. 그래서 "SD 는 아이브로우→제목이 48" 이라는 **틀린 결론**을 냈다 (실제로는 두 페이지 다 24). 반드시 `transition:none` + `transform:none` 을 **강제로** 넣고 잴 것. 프로토콜에 이미 있던 항목인데 건너뛰었다.
2. **주석 안에 닫는 구분자를 남기면 뒤가 전부 CSS 로 파싱된다.** 주석 중간을 편집하면서 `*/` 를 지우지 않아 뒤따르는 산문이 규칙으로 읽혔고, `.tblwrap` 풀블리드가 조용히 죽었다. 편집 후 주석 균형을 셀 것 (`check` 스크립트에 있음).
3. **공유 셀렉터는 페이지 셀렉터의 모양을 맞춰야 한다.** `.tbl th:first-child`(0,2,1) 는 base 의 `.tbl.wide th:first-child`(0,3,1) 에 진다. 나중에 로드돼도 상세도가 낮으면 아무 일도 안 일어난다.
