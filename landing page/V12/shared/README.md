## 왜 만들었나

이 폴더 전에는 페이지마다 자기 `<style id="v11-mobile-XX">` 를 들고 있었고, 같은 컴포넌트가 세 번 쓰여 있었다. 그리고 갈라졌다 — 2026-08-18 기준, **똑같은 마크업**인데:

| | Self-Directed | Managed |
|---|---|---|
| `.rows3 .row .t` 렛저 스텝 제목 | 22 / 400 / 1.25 | 17 / 500 / 1.15 |
| `.acct3 .a h3` 계좌 제목 | 22 / 400 / 1.25 | 17 / 500 / 1.15 |
| `.refuse` 목록 테두리 | 선만 (`border:0`) | 4면 박스 |

SD 가 그 규칙들을 **자기 파일 안에서만** 고쳤기 때문이다. 페이지 하나 늘 때마다 사본이 하나 늘고, 매번 손으로 맞춰야 했다. 이 폴더가 그걸 대체한다.

---

## 계약 (`v11.css` 맨 위에도 같은 내용)

1. **컴포넌트의 크기·두께·행간·자간·선 처리는 `v11.css` 가 소유한다.** 컴포넌트 클래스로 키를 잡는다. 페이지에 쓰지 않는다.
2. **페이지 블록은 `#섹션id` 리듬만 담는다** — 비트 사이 여백. (`Doctrine/Typography.md` §6b)
3. **페이지 예외는 `#id` 또는 `body.p-*` 로 키를 잡고, 바로 윗줄에 이유를 쓴다.** 조용한 오버라이드 금지.
4. **페이지 추가 = 이 파일을 링크하고 `<body class="p-sub">` 를 다는 것.** CSS 는 한 줄도 복사하지 않는다.

로드 위치: **페이지 자기 블록들 뒤, 마지막 스타일시트.** 같은 상세도에서 소스 순서로 이긴다. 각 페이지 base 시트는 이미 갈라져 있어서(SD 는 `.acct3 .a h3` 를 22 로, Managed 는 17 로 적어 뒀다) 이 파일이 다시 일치시키는 장치다.

## 페이지 하나 붙이기 — 3 단계

### 1. `</style>` 뒤에 링크 두 줄

페이지의 **마지막** `<style>` 블록 바로 뒤:

```html
<link rel="stylesheet" href="shared/v11.css">
```

스크립트는 원래 인라인 블록들이 있던 자리에 (보통 `</body>` 직전, `v9-mobile-js` 앞):

```html
<script src="shared/v11-sub.js"></script>
```

`defer` 를 붙이지 말 것 — 인라인 블록과 같은 시점에 실행돼야 한다.

### 2. `<body>` 에 페이지 타입 — **히로가 있을 때만**

```html
<body class="p-sub">
```

이게 서브페이지 히로(밴드 사진 위 · 검은 타이틀 블록 아래)를 켠다. 홈만 `p-home` 이고, 홈 히로는 `index.html` 이 계속 소유한다.

**히로가 없는 페이지엔 달지 않는다.** 아무것도 안 켜는 클래스를 다는 습관이 생긴다. 검사기도 히로가 있는 페이지에만 요구한다.

### 3. 페이지가 원래 들고 있던 중복 규칙을 지운다

그 페이지 `v11-*` 블록에서 `v11.css` 가 이미 말하는 규칙을 삭제한다. 남겨두면 계약 위반이고, 다음 사람이 어느 쪽을 고쳐야 하는지 모른다. **주석은 남긴다** — 근거는 살리고 중복만 지운다.

### 4. 검사

```bash
python shared/check-v11.py
```

## 선 규칙 — 그룹은 양끝을 닫는다 (2026-08-19 확정)

## 클로즈의 컨트롤 배치 (2026-08-19)

인경: *"managed는 cta가 self directed랑 open account / see pricing이랑 구분되어있고 sd에서는 같이 있어. 로직은?"*

**있던 로직 2개:**

1. **액션 그룹 = 박스 1 + ↗ 1.** 세 페이지 전부 그렇다. 홈 `OPEN AN ACCOUNT + READ THE MANIFESTO ↗`, SD `+ SEE MANAGED ↗`, Managed `+ SEE PRICING ↗`.
2. **`+` 는 액션 그룹 밖.** 표식 체계(§2-6) 그대로 — **↗ 는 화면을 떠나고 `+` 는 제자리에서 펼친다.** 액션 그룹은 "갈 곳" 목록이라 성격이 다른 `+` 는 그 아래에 둔다. SD 의 `VIEW THE RECORD DIAGRAM +` 가 그 경우.

**갈렸던 것:** Managed 의 `SELF-DIRECTED ↗` 는 ↗ 인데 그룹 밖, 그것도 프로즈 사이에 있었다. 다만 그 위 문단이 *"The record will tell you whether you are the exception."* 로 끝나 그 링크를 직접 가리키므로, **클로즈 CTA 가 아니라 그 문단에 딸린 인라인 exit** 으로 읽는 것이 맞다.

**문제는 위치가 아니라 소속이 안 읽히는 것이었다.** 위아래 24/24 라 문단 것인지 독립 컨트롤인지 알 수 없었다.

> **문장 → 인라인 컨트롤은 24 다.** 전 페이지 실측: `#development MANAGED ↗` 24, `#research PRICING ↗` 24, `VIEW THE FULL MEMO +` 24, `REGULATORY STANDING +` 24, Managed `SELF-DIRECTED ↗` 24.
>
> **그러므로 소속은 앞을 좁혀서가 아니라 뒤를 열어서 보인다** (인경). 프로즈 컬럼을 끝내는 exit 링크 뒤에 **48** 그룹 경계를 둔다.

처음엔 앞을 24→16 으로 좁히려 했는데 그러면 위 캐논을 깬다. 규칙은 `v11.css` §4h 에 있고 **링크에 걸려 있다** — `.cols` 그리드에 걸면 홈이 깨진다 (홈은 같은 그리드를 쓰는데 `.ccol` 이 비어 있어 24 가 다른 자리에서 읽힌다). SD 는 `.ccol` 의 마지막 자식이 `a.mlink` 가 아니라 `.v11-sview` 버튼이라 규칙이 닿지 않는다.

적용 후 Managed 클로즈:

```
아이브로우 →24→ 제목 →24→ 프로즈 →24→ 프로즈 →24→ SELF-DIRECTED ↗
   →48→ 가격줄 →8→ fee →48→ OPEN AN ACCOUNT →24→ SEE PRICING
```

48 두 개가 제안 블록을 앞뒤로 감싼다. 섹션 1067 → 1091. 홈(757)·SD(1021) 무변화 확인.

## ★ 크림 배경 페이지 — 2026-08-19 조사 결과

인경: *"다른 페이지는 크림색 배경인것도 있어서 검토후 진행해야함"*

`v11.css` §4a 의 헤어라인 색(`c-800`)은 **검은 면 전제**로 조건 없이 걸린다. 크림/흰 면에서는 `rgba(28,28,28,0.16)` 이 맞는 값이라, 크림 페이지가 그 컴포넌트를 쓰면 틀린 선이 그려진다.

**9 페이지 전수 조사 결과 — 지금은 위험 0.**

| | `.tri` `.acct3` `.refuse` `.v9band` `.rows3` `.fgrid` `.close9` `.trust9` | 푸터 |
|---|---|---|
| index · self-directed · managed | 사용 (전부 검은 면 위) | 검정 |
| pricing · manifesto · newsroom · press-release · changelog-entry · get-the-app | **하나도 없음** | 검정 |

크림 페이지들이 공유 파일에서 받는 건 `.mlink` 표식, `.menuov` 28, 데스크탑 타입 플로어, 22 티어, 푸터 2열뿐 — **전부 배경과 무관한 규칙**이다. 밝은 면에 있는 `.rows3`(`#how-it-works`)·`.pflist`(`#portfolios`)·표(`#track-record`)는 `.16` 을 그대로 쓰고 공유 파일이 건드리지 않는다.

**언제 손봐야 하나** — 밝은 면 페이지가 저 컴포넌트 중 하나를 처음 쓰는 날. 그때의 해법은 그 페이지에 오버라이드를 붙이는 게 아니라 **면이 선언하는 `--hair` 토큰**이다:

```css
:root{--hair:rgba(28,28,28,0.16)}   /* 밝은 바닥 */
.on-dark{--hair:var(--c-800)}       /* 검은 섹션이 스스로 표시 */
```

지금 안 한 이유: 9 페이지 전부에 검은 섹션 표시를 달아야 하는데, 아직 존재하지 않는 경우를 위한 작업이다.

**페이지 이식 후 콘솔에 붙여 확인:**

```js
[...document.querySelectorAll('.tri,.acct3,.refuse,.v9band')]
  .map(e=>{let n=e,bg='';while(n&&!bg){const c=getComputedStyle(n).backgroundColor;
    if(c!=='rgba(0, 0, 0, 0)')bg=c;n=n.parentElement}return e.className+' on '+bg})
```

검정(`rgb(0, 0, 0)`) 이 아닌 결과가 나오면 `--hair` 작업을 먼저 해야 한다.

## 아직 공유가 아닌 것 — 알고 있을 것

- **홈의 스크립트.** 홈은 자기 히로, 자기 푸터 빌더를 갖고 있고 reveal 은 `script#v11-mobile-js` 안에 있다. `v11-sub.js` 를 로드하지 않는다. 통합은 별도 작업 + 별도 검증.
- **한 페이지 전용 컴포넌트.** 홈의 `.latest` `.sys` `.loop3` `.std5b` `.def4` `.gap2` `.clog`, SD 의 `.sheet` `.specimens` `.constfig` `.v11-sview`, Managed 의 `.pflist` `.tbl` 은 각자 페이지에 있다. 두 번째 페이지가 쓰기 시작하면 그때 옮긴다 — 검사기가 알려준다.
- **공유용 단일 파일 빌드.** 깃헙/공유용으로 `shared/*` 를 각 HTML 에 인라인하는 빌드는 아직 없다. 지금은 `shared/` 폴더도 같이 올려야 한다.
