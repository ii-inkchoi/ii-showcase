Self-Directed System — Two Flows

Calibration is a one-time ritual fired when a user first chooses Self-Directed. Decision Gates fire on every trade thereafter, replaying the user's stored standards. Below: every screen of both flows, in order, with a one-line rationale per step.

Flow A

Calibration ritual — one time

Fires the moment a user actively switches to Self-Directed mode. Ends when the first Self-Directed account opens. Captures the standards that the Decision Gate will replay on every subsequent trade.

A3 · S1

Responsibility transfer

First screen sets the stakes. No friendly framing — the system states what is about to be transferred and what will be recorded.

Self-directed investing transfers responsibility to you.

You will make the decisions.

You will own the errors.

The system will record both.

A4 · S2

Reality check (1st text input)

Establishes the baseline statistical reality (most investors lose to the market) and asks the user to commit a 1st-person statement on when they personally misjudge.

You will likely not beat the market.

Most investors do not.

Most professionals do not.

Failure is rarely caused by missing information.

It is caused by poor judgment under uncertainty.

Keep it short and specific.

62/180

A5 · S3

Past errors (multi-select)

Inversion: before chasing edge, name your failure modes. Multi-select captures the full pattern; the next screen forces a single most-likely repeat.

Start with failure.

Before trying to outperform, identify how you are most likely to fail.

A6 · S4

Repeated error + trigger

Dynamic step: only the errors selected in S3 appear here. User picks the single most dangerous, then names what triggers it.

Replay target Buy gate / Volatility intervention

One repeated error matters more than ten isolated ones.

A system improves only when failure patterns are made explicit.

Which error is most likely to hurt you again?

A brief, concrete trigger is enough.

43/180

A7 · S5

Standard of entry — weakest definition

Names the three required components of a position (thesis / horizon / falsification condition), then asks which the user defines least clearly.

No position should exist without a reason.

Before capital is allocated, three things should be defined: a thesis, a time horizon, and a condition for being wrong.

Which of these do you define least clearly today?

A8 · S6

Claimed edge

Forces the user to articulate a single sentence claim. The act of writing it is the friction; the fact that it will be replayed is the consequence.

Replay target Buy gate

Active investing is not assumed.

It is not a default setting.

It is a claim.

Claims require evidence.

One clear sentence works best.

58/180

A9 · S7

Condition for action

Forces a verifiable condition before opening a position. This is the primary text the Buy gate replays.

Replay target Buy gate (primary)

Activity is not the objective.

A trade is not progress.

Access is not edge.

Action without a clear condition is usually noise.

Write a condition you can verify.

61/180

A10 · S8

Reconsideration triggers (multi-select)

Names the legitimate reasons to revisit a position vs. the noise (price volatility alone). The Sell gate replays the user's selections.

A position should not be reviewed because price moved.

Price movement is common.
A broken thesis is different.

A11 · S9

Weakness environment

Names the moment the user is most prone to bad decisions. The Sell gate and Volatility intervention replay this.

In consequential domains, speed is overrated.

The purpose of friction is not delay.
